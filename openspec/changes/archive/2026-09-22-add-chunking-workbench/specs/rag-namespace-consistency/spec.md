# Spec Delta

## Purpose

使知识库问答的各读操作与其写入落在同一个命名空间上，并让「当前读写的是哪个命名空间、
其中有多少内容」在使用者初始化助手时直接可见。

命名空间读错时的表现是**检索到别处的文档**或**什么都检索不到**，两者都不产生错误信号——
不会抛异常，检索耗时与相似度分数也都正常。因此这条一致性无法靠异常发现，只能靠契约约束
与把实际读写的位置显式呈现出来。

## ADDED Requirements

### Requirement: 读路径与写入同命名空间

知识库问答的各读操作——提问、检索、统计，以及回看与清理所依赖的 chunk 枚举——SHALL 使用
该助手写入时所用的同一命名空间。系统 MUST NOT 依赖底层对命名空间的默认取值。

#### Scenario: 提问检索本命名空间的内容
- **WHEN** 使用者以某一身份初始化助手，并就该身份已入库的文档内容提问
- **THEN** 系统检索到的内容来自该身份的命名空间，且答案引用的来源为该命名空间下的文档

#### Scenario: 空命名空间不串到其他命名空间
- **WHEN** 使用者以一个没有任何内容的命名空间初始化助手并提问
- **THEN** 系统报告未检索到内容，而不是回落到其他命名空间下的文档

#### Scenario: 回看只呈现本命名空间的内容
- **WHEN** 使用者查看一份已入库文档的切分结果，且同一路径的文件在另一命名空间下也存在
- **THEN** 系统只呈现该助手命名空间下这份文档的 chunk

### Requirement: 命名空间状态在初始化时可见

助手初始化时 SHALL 报告其实际使用的命名空间，以及该命名空间下已入库的 chunk 数量。
该命名空间下没有任何 chunk 时，系统 SHALL 明确提示这将导致问答检索不到内容。

#### Scenario: 初始化报告命名空间与容量
- **WHEN** 使用者以某一身份初始化助手
- **THEN** 系统展示该身份的命名空间标识与其下已入库的 chunk 数量

#### Scenario: 空命名空间给出提示
- **WHEN** 初始化时该命名空间下没有任何 chunk
- **THEN** 系统提示问答将检索不到内容，并提示该身份的文档可能尚未入库

#### Scenario: 计数读取失败与空命名空间可区分
- **WHEN** 初始化时无法读取该命名空间的 chunk 数量
- **THEN** 系统报告读取失败，而不是把它显示为 0 块
