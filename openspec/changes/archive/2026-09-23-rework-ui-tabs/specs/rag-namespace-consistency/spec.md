# Spec Delta

## ADDED Requirements

### Requirement: 读写与删除同命名空间

知识库问答的各读操作——提问、检索，以及文档清单与删除所依赖的 chunk 枚举——SHALL 使用
该助手写入时所用的同一命名空间。系统 MUST NOT 依赖底层对命名空间的默认取值。

#### Scenario: 提问检索本命名空间的内容
- **WHEN** 使用者以某一身份初始化助手，并就该身份已入库的文档内容提问
- **THEN** 系统检索到的内容来自该身份的命名空间，且答案引用的来源为该命名空间下的文档

#### Scenario: 空命名空间不串到其他命名空间
- **WHEN** 使用者以一个没有任何内容的命名空间初始化助手并提问
- **THEN** 系统报告未检索到内容，而不是回落到其他命名空间下的文档

#### Scenario: 清单只呈现本命名空间的内容
- **WHEN** 使用者查看知识库文档清单，且同一路径的文件在另一命名空间下也存在
- **THEN** 系统只依据该助手命名空间下这份文档的 chunk 给出其块数与质量度量

#### Scenario: 删除只作用于本命名空间
- **WHEN** 使用者删除一份已入库文档，且同一路径的文件在另一命名空间下也存在
- **THEN** 只有该助手命名空间下这份文档的 chunk 被删除，另一命名空间下同路径的 chunk
  数量与内容保持不变

## REMOVED Requirements

### Requirement: 读路径与写入同命名空间

**Reason**: 正文列举的读操作里有「统计」与「回看」两项，本次改造把两者都去掉了——
「统计」随学习报告一起消失，「回看」连功能一起删除；而其中一条 scenario
（`回看只呈现本命名空间的内容`）的观察面正是被删掉的那个界面。校验与归档都不允许
MODIFIED 丢掉 scenario（归档会以「current spec contains scenario(s) not present in the
modified block」拒绝），所以这条约束只能整条换名重写。约束本身**没有**被删除：正文与
两条原样保留的 scenario（`提问检索本命名空间的内容`、`空命名空间不串到其他命名空间`）
逐字移入 `读写与删除同命名空间`。

**Migration**: 无。这是同一条约束换了名字、并把读操作清单改为「提问、检索，以及文档清单
与删除所依赖的 chunk 枚举」。验收断言不变，且新增的 `删除只作用于本命名空间` 比被替换的
`回看只呈现本命名空间的内容` 断言的是更危险那条路径——删除是唯一会改动知识库的读侧操作，
`_document_point_ids` 的双条件过滤（`chunking.py:1488-1520`）本就是为它写的。
